# 模拟电信客户流失业务材料

本文是为原型测试编写的模拟业务文档，不含真实客户信息。

## 客户流失预测能力与输入输出
客户流失 churn 是二分类标签，1 表示流失，0 表示留存。输入为 tenure（使用月数）、monthly_charges（月费用）、support_calls（客服次数）、contract（合同类型）、payment_method（支付方式）。输出为每位客户的流失概率，范围 [0,1]，顺序与输入一致。禁止把客户标识、取消日期、流失后的退款信息作为特征。

## 缺失值和类别编码策略
数值特征使用训练集的中位数填补，再标准化。类别特征用训练集众数填补并做独热编码。上线时合同类型可能出现未知类别，编码器必须允许未知类别，例如 handle_unknown='ignore'。预处理器必须放在 Pipeline 中，仅在训练集拟合，防止数据泄漏。

## 候选算法及适用条件
逻辑回归适合可解释的线性基线，配合标准化和 class_weight='balanced'。随机森林适合非线性关系和特征交互，限制树深度、叶节点样本数与 n_jobs，控制过拟合与资源消耗。两者应使用同一份数据划分比较。

## 评价指标与业务约束
客户流失预测使用 ROC-AUC 比较概率排序能力，同时报告 F1 与 accuracy，不能仅用准确率说明不平衡任务表现。原型约定 ROC-AUC >= 0.65 且 F1 >= 0.45 为演示门槛；这些不是实际业务验收标准。候选选择和修复只用验证集，保留测试集只对最终选定代码评估一次。

## 环境与模型交付
Python >= 3.11，使用 scikit-learn、pandas、numpy、joblib。生成模块须提供 build_model(seed=42) 和 predict(model, frame)，保存模型后重新加载的预测应保持一致。模型文件只能从可信来源加载。

## 历史失败案例：未知类别
历史示例在合同类型出现新取值时抛出 Found unknown categories 错误。解决方法是 OneHotEncoder(handle_unknown='ignore')，并加入未知类别的回归检查。本段为预置模拟经验，运行中产生的失败另行保存，并标注是否故障注入。
