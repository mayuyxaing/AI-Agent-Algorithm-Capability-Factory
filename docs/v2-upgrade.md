## 升级内容

| 环节 | v1 | v2 |
|---|---|---|
| 需求解析 | 只检查任务和标签，曾接受 strings 占位值 | 约束枚举校验，检查缺失值、未知类别、不平衡等明确要求是否漏提 |
| 数据利用 | 主要由固定模板决定处理 | 训练集画像：样本量、缺失率、基数、分位数、类别比例和常量列 |
| 知识检索 | 词语重叠排序 | Requirement → Strategy → Knowledge/Function 两跳遍历，结合词语排序，返回路径 |
| 实现规划 | 候选算法和文字理由 | 明确预处理策略及有边界的超参数，理由结合训练数据统计 |
| 代码生成 | 提供完整参考实现 | 真实模型只接收接口规范、画像、计划和检索知识；mock 仍在内部使用模板 |
| 独立验证 | 接口与指标 | 增加分类器类型、超参数、随机种子、线程数及预处理与计划的一致性检查 |
| 修复演示 | mock 模板故障 | 可在真实模型原始代码上显式修改 OneHotEncoder，再由模型读取验证反馈修复 |
| 实验 | 单次工程示例 | 相同数据/划分/生成上限的三组对照，记录通过率、调用、tokens 和修复次数 |

## 怎么演示新版

普通真实流程：Win+R 启动 cmd.exe /k 加上 run-glm.cmd 的完整路径，和之前操作相同。旧响应会因提示词、输入和工作流身份变化而失效，不会把旧模板参考运行当作新版结果。

显式缺陷与真实修复：使用 `repair-glm.cmd`（或 `python scripts/run_glm.py --run --repair-demo`）。先由模型自主生成，再由宿主将初版逻辑回归的 OneHotEncoder.handle_unknown 改成 error；原始响应保存在 model_response.py，实际执行版本为 algorithm.py。报告明确记录 injected=true、fault_origin 和两个代码摘要。验证失败后，repair 接收旧代码及结构化反馈。若模型没使用 OneHotEncoder，演示明确停止，不假称已注入缺陷。

**这个案例只能说明模型修复了显式注入的缺陷，不能算作自然生成错误的成功修复证据。** 即使最终通过，也要在答辩中说明故障来源。

对照实验：`benchmark-glm.cmd` 或 `python scripts/run_glm.py --benchmark`。默认一个 baseline 数据条件、seed=42，三组依次运行，比单次主流程需要更多时间。结果在 runtime/glm/benchmark-v2/summary.md。中断后重复同一命令可续跑。

## 对照协议

- direct：接口、训练画像和有界算法空间；不提供检索知识/历史经验。失败后可独立重采样，不接收旧代码或验证反馈。
- knowledge：增加同一固定文档/AST 语料的图谱检索；仍独立重采样，不提供修复反馈。
- knowledge_repair：同样的知识，在失败后提供旧代码及验证反馈。
- 每组每候选的生成次数上限相同（默认 3）；首次通过即停止，所以实际调用和 token 消耗可不同。两组基线不是强制只生成一次。
- 规划阶段提供机器可读 output_schema。各组都允许一次结构化格式纠正；这与代码执行反馈修复分开记录，不把格式不合规自动填成默认算法。所有返回内容在校验前写入 *_response 事件，失败写 *_rejected，只有核对通过的结果进入检查点。
- 每个 case/seed 使用完全相同的数据与分层划分，数据库分离；对照语料固定为规则/AST 抽取，避免把不同 LLM 抽取结果混成另一个实验因素。
- 训练画像只来自训练集；方案选择及修复使用验证集；每组只对最终版本评估保留测试集。
- 服务错误单独统计，未运行的任务不计为算法失败。JSON/计划契约失败属于模型产物失败，不能排除以美化成功率。
- reported_tokens 汇总 API 返回的 usage 及续跑前已有尝试，缺少 usage 的失败请求无法纳入；mock 的 0 tokens 不表示真实模型免费政策。

扩展数据条件和种子示例（需要先在自己的终端配置 ZHIPU_API_KEY）：

```powershell
python -m forge benchmark --provider glm --cases baseline missing_high minority --seeds 42 43 --rows 600 --output runtime/glm/benchmark-expanded
```

这将产生 18 个实验单元。先跑默认的三个单元核对行为，再决定是否扩展；不能提前声称存在提升或统计显著性。

协议包含提示词摘要与格式纠正上限；提示词或协议改变后，旧 campaign 会拒绝直接续跑，应选择新的输出目录。历史离线示例保留原协议，不修改成新实验结果。

离线实验示例见 examples/v2/benchmark/summary.md。Mock 在各组使用相同的规则/模板，不能用它的组间指标评价真实 LLM 知识增强效果。

## 边界与后续工作

当前仍是固定字段二分类，有两个分类器；尚无跨场景迁移或 MCTS。图关系由可审查的关键词规则构建，遍历是固定两跳，不能称为通用图推理。模型参数选择受限于公开的有界空间，验证要求显式 ColumnTransformer 数值/类别分组。这有利于复现，但限制了任意实现方式。

增加算法时，需要同步增加规划空间（planning.py）、插件元数据、模板和 worker 类型/计划检查；只放一个 JSON 不足以扩展完整 v2 契约。自然语言数字门槛仍不自动覆盖独立验收配置。子进程不是安全沙箱。
