# 五分钟项目演示讲稿

## 0:00–0:40　问题与目标

我实现的是一个算法能力工厂原型。我的出发点是，算法经验通常分散在业务文档、历史代码和实验记录中，单次代码生成没有把这些经验与验证结果连接起来。

因此，我将系统设计成闭环：从材料中抽取能力，理解自然语言需求，检索知识并规划方案，生成代码后独立验证，再按反馈修复，最后保存版本和经验。

本项目以客户流失预测为主场景，再扩展到客服工单文本分类。

## 0:40–1:20　架构与知识

我先展示材料和图谱。客户流失文档包含字段、缺失值、未知类别和评价要求，历史代码示例提供函数级经验。

抽取后，知识保留来源文件、内容摘要和原文片段。图谱还包含能力、策略、算法版本、验证运行和失败案例。

系统根据任务约束沿“需求—策略—知识”路径检索，将相关知识与历史失败交给规划角色。存储采用 SQLite，便于本地复现与导出。

展示文件：[业务材料](../materials/churn_business.md)、[图谱 schema](schema.md)、[图谱视图](../examples/v3/text-assisted-repair/runs/20261115T045921Z-76a2bd42/knowledge_graph.html)。

## 1:20–2:30　客户流失真实生成与修复

这里展示真实 GLM 运行。输入需求要求处理缺失值、未知类别和类别不平衡，并比较候选方案。

规划包含算法、参数、预处理和证据 ID。模型生成代码后，宿主调用统一接口训练和检查。

为了演示反馈修复，我让宿主对生成的编码器显式注入未知类别故障。第一次验证检测到错误，GLM 根据反馈修复，下一轮通过。这里可以对比原始输出、注入版本和修复版本。

最终选中逻辑回归，测试 ROC-AUC 为 0.7829，F1 为 0.6432，12 项检查通过。测试结果没有用于修复或重选方案。

展示文件：[真实报告](../examples/v2/real-success/report.md)、[交接轨迹](../examples/v2/real-success/events.json)、[修复后代码](../examples/v2/real-success/logistic/attempt_1/algorithm.py)。

## 2:30–3:30　文本迁移与半自动修复

接下来是工单紧急程度分类。我复用同一工作流，将输入改为 text 列，接入字符 TF-IDF、逻辑回归和多项式朴素贝叶斯。

真实 GLM 自主尝试中，清洗器没有正确处理 DataFrame，导致样本数量不一致。我保留了失败记录，在开发阶段借助编码助手增加提取 text 列的接口补丁。

修正后两个候选通过验证，按配置的 F1 和候选顺序选择逻辑回归。测试 ROC-AUC 为 0.8701，F1 为 0.8765。这个案例记录为半自动修复，可查看原始失败与逐行补丁，也可不调用 API 重新训练复现。

展示文件：[文本案例](../examples/v3/text-assisted-repair/README.md)、[接口补丁](../examples/v3/text-assisted-repair/sources/text_nb/interface.patch)、[完整报告](../examples/v3/text-assisted-repair/runs/20261115T045921Z-76a2bd42/report.md)。

## 3:30–4:20　验证与沉淀

我把验证独立放在宿主侧。模型负责生成代码，评估标签保留在宿主，指标由宿主计算；同时检查概率接口、缺失输入、未见词表、重复预测和保存重载。

运行结束后，每版源码摘要、指标、环境和失败原因写入图谱，后续任务可检索同一任务下的失败经验。算法、任务和指标也有注册接口。

目前归档了 148 项测试通过记录。文本半自动案例已完成提交包解压后的独立复现。

## 4:20–5:00　总结与后续研究

我完成的核心工作，是把知识抽取、受约束生成、独立验证和经验沉淀连接为可追溯流程，并在表格与文本场景中验证复用方式。

当前采用模拟数据和串行多角色调度。我已完成 27 单元真实 GLM 对照，直接生成、知识增强和知识增强加修复分别通过 4/9、8/9、4/9。本轮知识增强组完成率最高，但修复组没有取得更高总体通过率，规划失败是主要限制。下一步增加固定任务的重复采样，改进规划引用与执行隔离。
