# 验证覆盖、知识更新与实验续跑

我对验证器、知识检索和对照实验的状态管理做了三项修正，并增加了对应回归测试。

| 原有缺口 | 修改后的行为 | 验证方式 |
|---|---|---|
| 只在 contract 字段注入未知类别，支付方式的缺陷可能漏检 | 对每个类别字段分别测试整批未知值、已知与未知值混合输入，再测试所有类别字段同时未知；每项单独记录结果 | 注入只在指定字段出错、只在混合批次出错的预测器，检查验证器逐项拒绝 |
| 新旧文档事实同时参与词法排序和图谱路径加分 | 每个材料目录维护已提交知识快照，更新或删除文档后，旧事实保留但不参与默认检索；整个目录抽取成功后才切换快照 | 高重叠旧文本不能压过新文本；删除、抽取中途失败、多语料同名文件与图谱导入导出均有测试 |
| 同一对照单元续跑复用已写入失败经验的数据库 | 已完成单元通过报告摘要核对后跳过；服务中断单元创建新 attempt 目录、全新数据库，从固定语料重新开始，不使用前次响应缓存 | 在前次数据库写入可复用的“污染经验”，重启后确认其未进入新数据库；篡改数据、报告或执行身份时拒绝续跑 |

## 知识快照

`source_versions(source_id, corpus, path)` 记录来源归属，`active_facts(corpus, fact_id)` 记录当前可检索事实。`corpus` 使用材料目录的规范绝对路径，不同目录的同名文件相互独立。`nodes()` 和图谱导出仍包含历史版本，`current_facts()` 是默认检索入口。历史 Strategy 边也会经过当前事实过滤，不能绕过版本约束。

目录抽取前先读取一份材料内容快照，来源摘要与实际抽取使用同一份文本。抽取失败时留下审计与待发布节点，当前快照保持不变。JSON schema 1.1 增加 `retrieval_state`，通过 `KnowledgeStore.import_graph()` 恢复时保留生效状态。

旧版图谱没有语料归属信息，第一次成功重抽取时，将未归属的旧来源绑定到该目录并退出默认检索。旧 GLM 材料缓存需要刷新一次后才能复用。多目录项目应保持目录身份稳定；移动材料目录会被视为新语料，不自动合并。

## 对照实验续跑协议

协议 v3 绑定代码、模板、算法注册表、Python 与已安装依赖版本、提示词、供应商配置、语料、种子及验证策略。端点仅保存摘要，不保存可能包含凭据的原始地址。每次续跑重新生成预期数据并核对字节内容，同时核对已完成单元的报告摘要。任一条件变化都需要新实验目录。

服务中断后的处理是**重启该单元**，不是在原候选内部继续执行。每次尝试的候选生成上限相同，前次尝试的报告和 API 已报告 tokens 保留在 `prior_attempts`，费用统计包含前次尝试。中断本身仍可能造成选择偏差，因此报告单独列出中断和重试，不能把重试后的成功率解释为一次生成的成功率。

默认 GLM 对照入口改用 `runtime/glm/benchmark-v3/`，旧 v2 实验记录保留；不能将旧记录直接续接为新协议。

## 本地复现

```powershell
python -m pytest -q tests/test_review_regressions.py
python -m forge benchmark --provider mock --rows 200 --output runtime/review-benchmark-v3
# 原命令再次运行：核对输入和报告后跳过已完成单元
python -m forge benchmark --provider mock --rows 200 --output runtime/review-benchmark-v3
```

回归测试覆盖这三项已知缺口，不证明所有未知类别分布均被穷举，也不提供恶意代码安全保证。历史真实模型报告维持原样，新检查不会追溯修改原来的通过标记。离线对照用于验证状态隔离，没有新增真实模型效果结论。

本轮完整测试为 **148 项通过、0 项失败**。另外，我通过 CLI 完成了 baseline/seed=42、200 行模拟数据的三组离线运行，三个单元均通过；再次执行相同命令跳过了全部完成单元，没有新增 attempt 目录。离线结果见 [summary.md](../examples/review/benchmark-v3/summary.md)，协议与目录索引见 [manifest.json](../examples/review/benchmark-v3/manifest.json)。这次运行不使用真实 LLM。
