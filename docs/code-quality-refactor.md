# 核心代码重构与验收

我将本轮修改集中在工作流职责、数据契约、错误分类和事务完整性上。

## 模块职责

| 模块 | 负责的行为 |
|---|---|
| `workflow.py` | 按顺序调用阶段、保留候选进度、处理运行级失败 |
| `contracts.py` | 任务描述、候选计划、实现计划、运行选项、验证策略与验证结果的类型及运行时校验 |
| `workflow_stages.py` | 需求理解、知识上下文、规划，以及选中候选的最终测试 |
| `candidate_execution.py` | 单个候选的代码生成、有限修复、源码保存与验证；不接收测试集 |
| `session.py` | 模型调用、响应缓存和事件记录；复制输入输出，避免后续修改污染历史 |
| `run_artifacts.py` | 环境元数据、报告与图谱输出；持久化失败单独报告 |
| `knowledge.py` | 保留原有 `KnowledgeStore` 公共接口，委托给下面各模块 |
| `knowledge_repository.py` | SQLite 连接、节点与边、快照状态、事务、图谱导入导出 |
| `extraction.py` / `source_documents.py` | 材料解析、模型事实引证核对、抽取审计与快照发布 |
| `retrieval.py` | 生效知识过滤后的词法排序和规则图谱遍历 |
| `run_history.py` | 一次运行及其版本、环境、指标、失败经验的事务化写入 |
| `provenance.py` | 工作流响应缓存与对照实验共用的代码、插件、环境和供应商身份 |

重构前，`run()` 为 215 行；重构后为 64 行。这个变化用于说明职责已被移出入口函数，质量验收仍以各模块的行为和失败处理为准。CLI 参数和主要报告字段保留，新运行使用 `workflow_version=3`；旧响应检查点不会直接混入新流程。

## 数据和错误边界

模型响应先经过任务校验和通用契约解析，再进入执行阶段。计划中的候选 ID 必须可作为安全目录名，超参数和预处理字典在输入、输出边界复制。CLI 配置和程序直接调用 `run()` 使用同一验证策略解析，拒绝布尔值阈值、非有限数值及非法预算。

模型返回的代码结构错误仍使用原有修复预算。网络及供应商错误终止运行。适配器的程序异常、宿主验证结果缺少指标、`passed=true` 却含失败检查等情况按内部错误终止，不将这些错误交给模型修复。

最终测试集只交给 `final_evaluation()`。候选执行器只持有训练集和验证集。测试失败后不重新选模型、不回流修复。

## 事务与文件

一次运行的运行记录、版本、环境、指标及关系在同一 SQLite 事务内保存。图谱导入中途失败时回滚；文档快照生效状态、成功审计和规则索引一起提交。嵌套事务共享连接，内层异常即使被捕获，也会使外层回滚。连接在上下文退出时关闭。

模型调用和材料抽取不会长时间持有发布事务。抽取中间产物保持待发布状态，成功时才切换快照。JSON 使用同目录临时文件原子替换，序列化或替换失败不会截断已有文件。

数据库与文件系统之间没有分布式事务。图谱生成失败时数据库回滚，报告标为 `persistence_failed`，删除该次不完整图谱。机器崩溃时的跨介质恢复仍需进一步设计。仓库实例按单个串行工作流使用，不支持在线程之间共享活动事务。

## 验收方式

```powershell
python -m pip install -r requirements-dev.txt
python -m compileall -q forge scripts
python -m pytest -q tests/test_architecture_boundaries.py
python -m pytest -q
```

[边界测试](../tests/test_architecture_boundaries.py) 注入了模型适配器错误、矛盾验证结果、图谱外键错误、快照发布错误、运行写入错误和文件替换错误，并检查事件记录与模型上下文不会被后续修改。

[CLI 复核摘要](../examples/refactor/cli-smoke.json) 记录客户流失故障修复与文本分类的离线调用结果。完整 CLI 复现沿用 README 的 init/run 命令。历史真实 GLM 报告保持原样，本轮没有新增真实模型效果实验。

我增加了 [GitHub Actions](../.github/workflows/tests.yml)，配置 Python 3.11 和 3.12 的离线回归任务，不需要模型密钥。该配置的云端结果要在推送后查看，本地通过记录不代表云端已经执行。当前没有引入全项目严格静态类型检查。
