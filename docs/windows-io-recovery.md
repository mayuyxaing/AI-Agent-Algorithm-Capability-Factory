# Windows 文件写入中断恢复

正式实验在完成 9 个单元后，写入第 10 个单元的 events.json 时遇到 WinError 5。前 9 个单元中有 6 个通过、3 个规划失败。我保留了所有原始结果和中断目录。

我为 JSON 原子替换增加了最多六次 Windows 临时访问冲突重试，等待间隔为 0.1、0.2、0.4、0.8、1.6 秒；持续失败仍会退出，保留旧文件，不修改文件权限，也不使用直接截断覆盖。

这次修复改变了 forge/util.py 的内容，因此不能直接忽略实验的代码摘要检查。我通过 scripts/recover_windows_io.py 核对了旧源码摘要，确认除了工具文件外，其余模型调用、算法、验证与数据处理源码均未变化；已有 9 份报告摘要均通过校验。原始 manifest 保存为 manifest.before-windows-io-hotfix.json，兼容性变更记录为 windows-io-hotfix.json，当前清单只更新执行代码摘要。

模型、提示词、数据、种子、生成预算和验收策略保持原值。重新运行 benchmark-full-glm.cmd 会跳过已有最终结果的 9 个单元，从高缺失条件的中断单元创建新尝试。该尝试未形成完整报告，部分 API 用量无法恢复，成本按未知记录，不记作零。

文件重试、失败保留、恢复脚本拒绝非工具代码修改以及现有缓存恢复的针对性回归检查共 9 项通过。临时占用的具体来源尚未确定；持续权限问题仍需要单独排查。
