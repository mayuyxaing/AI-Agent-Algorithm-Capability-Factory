# 核心代码讲解提纲

我按一次任务的实际调用顺序讲解代码，区分模型负责的产物和宿主负责的决策。

## 1. 入口与阶段契约

入口为 [cli.py](../forge/cli.py) 的 `main()`，任务执行进入 [workflow.py](../forge/workflow.py) 的 `run()`。我先解析验证策略，确定任务插件和算法目录，建立运行目录、事件会话和报告。

[contracts.py](../forge/contracts.py) 定义任务、候选、实现计划、运行选项、验证策略与验证结果。模型传回 JSON；宿主完成类型、字段、引用和参数范围检查后，内部阶段才使用这些记录。保留 JSON 审计格式，方便核对模型原始输出。

## 2. 理解、知识与规划

[workflow_stages.py](../forge/workflow_stages.py) 的 `prepare_task()` 划分数据，只从训练集生成画像，然后请求需求理解。`retrieve_context()` 根据画像与约束检索，`plan_candidates()` 校验候选、参数、预处理和证据引用。

知识公共入口为 [knowledge.py](../forge/knowledge.py)，抽取、检索和存储分别位于 extraction、retrieval 和 knowledge_repository 模块。检索读取 `current_facts()`：历史节点保留，但默认只返回已提交的生效集合。整个材料目录成功抽取并完成发布后才切换快照，删除的文档也会退出生效集合。

理解、规划与抽取的单层 `answer` 解包位于 [structured.py](../forge/structured.py)。它只接受唯一、单层对象，不补写缺失字段，也不把虚构证据 ID 改成空数组。格式纠正有单独预算，当前最多一次。

## 3. 候选生成、反馈与验证

[candidate_execution.py](../forge/candidate_execution.py) 的 `CandidateExecutor` 只接收训练集与验证集，不接收测试集。模型生成的每版源码先保存，再调用评估器。修复组第二次及以后调用会收到前一版源码和验证反馈；另外两组独立重采样，不接收这些反馈。

配置 `max_repairs=2` 表示最多初版加两次修复，每次尝试中每候选上限三版。格式错误可消耗生成预算，供应商故障和宿主程序错误会终止该次运行。中断单元重启后会使用新数据库，累计生成次数可能超过一次尝试的上限，因此报告单独列出重启与成本。

[validation.py](../forge/validation.py) 负责静态检查、启动子进程、超时和宿主指标计算。[worker.py](../forge/worker.py) 负责训练与接口测试。子进程获得训练标签和待预测特征，不获得验证或测试标签。宿主校验概率向量并计算指标；通过条件由布尔检查及配置门槛共同决定。

客户流失任务在 [tasks.py](../forge/tasks.py) 中逐一检查 contract 和 payment_method 的未知类别，包含整批未知与混合已知/未知输入，再检查两个类别字段同时未知。它覆盖当前任务契约，不穷举任意数据分布。

## 4. 选择、测试与沉淀

`final_evaluation()` 按验证集配置指标选择通过的候选，再对选中版本进行最终测试。测试失败是终止状态，不重新修复或选择模型。

[run_artifacts.py](../forge/run_artifacts.py) 整理报告与图谱，[run_history.py](../forge/run_history.py) 保存运行、版本、指标、环境及失败关系。图谱写入使用事务，失败时回滚。JSON 采用原子替换；Windows 临时访问冲突有有限重试。数据库和文件系统之间没有分布式事务，仍需明确报告持久化失败。

## 5. 根据一次失败定位问题

我先查看 `report.json` 的 status、failure_kind、error_stage，再沿 `events.json` 找到失败前的原始响应。规划失败先核对引用、候选及参数；候选失败先看 checks、check_errors、源码和错误日志；provider 错误查看供应商业务码与重试记录。

规划失败时还没有候选代码，不能通过增加代码修复轮数解决。正式实验的 11 个失败中有 10 个在规划阶段，这是后续改进的优先位置。

## 6. 讲解时需要区分的结论

- 148 项测试通过表示已有回归样例通过，不表示所有输入或生成代码都正确。
- 27 单元真实对照的通过数为 4/9、8/9、4/9，是本轮任务集上的观察结果，不代表稳定因果增益。
- 当前为串行多角色编排；图谱使用规则索引与固定路径遍历。
- 执行环境为受限子进程和静态检查，公共服务仍需操作系统级隔离。
- 开发中我借助编码助手进行实现、重构和测试；文本半自动案例的接口补丁单独保留，原始自主失败没有被改写。
