# 项目介绍

## 背景与目标

我关注的问题是：业务文档、历史代码和实验记录中已经存在的算法经验，能否被整理为可检索的能力知识，并进一步转化为经过验证的算法代码？

直接让大模型生成一个分类器，可以得到代码，但实现依据、验证过程和后续复用往往分散。我希望把这些步骤连接起来：任务开始时利用已有知识，任务执行时记录生成与修复过程，任务结束后把算法版本和验证经验重新沉淀到知识库。

因此，我设计了 Capability Forge 算法能力工厂原型。它接收自然语言能力描述，输出可运行代码、训练模型、验证报告和更新后的知识图谱。

## 我的主要工作

我首先选择客户流失预测作为主场景，整理模拟业务文档和历史代码，定义输入字段、标签、预处理约束与评价指标。随后将 Markdown 分段抽取、Python AST 抽取和 LLM 知识抽取接入同一存储结构，为每条知识保留来源、原文片段和内容摘要。

在工作流上，我将需求理解、知识检索、方案规划、代码生成、验证、修复和结果回写拆成独立环节。模型负责给出需求结构、候选计划和代码，宿主程序负责检查契约、执行算法和计算指标。生成结果不直接决定验证结论。

在验证上，我采用固定随机种子的训练、验证、测试划分。验证集用于修复和候选选择，最终测试集用于评估选定版本。同时检查未知输入、缺失数据、概率输出、重复预测和模型保存重载。

我还接入客服工单紧急程度分类，复用原有工作流，替换任务插件、输入契约、算法空间和验证配置。这个过程暴露了 DataFrame 与文本序列的接口问题，我保留了失败记录，并通过显式接口补丁完成半自动验证。

## 运行结果

客户流失任务完成了真实 GLM 的规划、代码生成和反馈修复。修复演示由宿主显式注入未知类别缺陷，再由模型根据验证反馈修复。最终选择逻辑回归，测试 ROC-AUC 为 0.7829，F1 为 0.6432。

文本任务比较字符 TF-IDF 与逻辑回归、多项式朴素贝叶斯的组合。在开发阶段完成输入接口修正后，两个候选均通过验证，最终选中逻辑回归，测试 ROC-AUC 为 0.8701，F1 为 0.8765。这个案例属于半自动修复，GLM 原始自主运行的失败状态保持不变。

项目归档了 148 项自动化测试通过记录，并完成提交包解压后的文本半自动复现。

## 当前范围与后续方向

当前原型支持两种固定输入契约的二分类任务，提供 CLI、候选比较、多轮修复、图谱可视化、版本记录及插件扩展。系统采用串行多角色调度；执行隔离目前是 AST 检查与受限子进程。

我已完成三条件、三种子、三组共 27 单元真实 GLM 对照，三组分别通过 4/9、8/9、4/9。知识增强组在本次任务集上的完成率最高，修复组未取得更高总体通过率。后续优先改善规划可靠性，增加固定任务的重复采样，并进一步完善执行隔离和任务扩展。
